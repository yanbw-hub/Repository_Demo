Production Order Schedules & Status System

Live SAP based production order schedules on an interactive Gantt chart, with a simulation view (playground integrated) and a source data table plus simple revenue calendar, built to support daily scheduling for key work centers.

How to use this system

  • Choose the view at the top of the app to select functions.
  • It may take 1-5 mins to load the data. Please wait.
  • Use the Workcenter and weeks to filter.
  • Refer to the Guide Manual for more information.
  • Data refreshes automatically at 0AM, 6AM, 12PM and 6PM.
  • The app is designed for all devices, including mobiles.

Guide Manual

The Production Order Schedules system shows the live SAP production order schedule on an interactive Gantt chart, plus an editable simulation view and a source data table with a simple revenue calendar. All views use the same merged dataset from the SAP production order schedule, sales backlog and backlog comments extracts.

  1. Purpose & when to use

    Use this system when you need a clear picture of which production orders are sitting on each work center in the coming weeks, with basic revenue and production line context.

    • Use it in daily or weekly scheduling meetings to walk through the queue by machine and by week.
    • Use it when you need to re-slot orders, check gaps or understand whether a proposed change will clash with existing work.
    • Use the NETWR_EURX and OmPeriod fields to support conversations with Sales and Management about priorities and timing.
  2. Top filters & views

    The top bar lets you switch views and control what is shown in both the Gantt and the data table.

    • Workcenter: choose a single work center (CNC, WELD, SETUP, WIND, ROVE, etc.). All rows and Gantt bars are filtered to that center.
    • Weeks selector: in Schedule and Simulation views, use the week “chips” to focus the Gantt on selected weeks. By default, the app picks roughly four weeks around “today” based on the schedule data.
    • View selector: the three buttons at the very top switch between Schedule Gantt, Simulation and Source Data Table, all sharing the same dataset.
    • Refresh behaviour: the Schedule view automatically reloads from /api/prodorderschedule around 00:00, 06:00, 12:00 and 18:00 so the view stays close to the latest SAP data without manual refresh.
  3. Reading the Schedule Gantt

    The Schedule view shows one row per “unit” of a production order, pinned information on the left and an interactive time axis on the right.

    • The pinned columns include Sales Order, Item, Production Order, Material, Package text, Rem hrs, Std hrs, Total Qty and Unit, all read directly from the merged SAP data.
    • Each bar on the right runs from Start date/time to End date/time. Orders with quantity > 1 are split into several units so it is easier to see where capacity is consumed across the week.
    • Completed or “done” work is rendered with a softer grey bar, while open work uses a blue gradient. Hover a bar to see a tooltip with order number, dates and hours.
    • Scroll horizontally to move through days. Use the week selector chips to keep the timeline focussed on the relevant 1–4 week window instead of the entire horizon.
  4. Simulation view & no-buffer mode

    The Simulation view reuses the same split layout but with fully editable rows that live only in your browser, so you can test different scenarios without touching SAP.

    • Upload an Excel file in either the existing simulation format or the schedule-style format; the app auto-detects the template and normalizes it to the same structure used by the Schedule view.
    • The “See schedule without buffers” option loads live data from /api/prodorderschedule and recalculates each bar length from Rem hrs while skipping weekends, so you can visualise a “no buffer” scenario.
    • You can adjust start / end times, edit the Production Order field, drag and drop rows, and insert or delete rows. The Gantt on the right updates in real time as you edit.
    • Use the Download Gantt as PDF button to export the current simulation view for review in meetings or email.
  5. Source data table & revenue calendar

    The Source Data Table view exposes the same dataset in a sortable table, plus a simple day-based calendar that highlights revenue by date.

    • The table shows one row per production order item, with Sales Order, Item, Order, Material, Short text, Act hrs, Rem hrs, Std hrs, Total Qty, Workcenter, Production Line, NETWR_EURX and OmPeriod fields.
    • Use the Workcenter selector and Production Line filter to focus on a specific cell or line when exploring orders or exporting data.
    • The revenue calendar groups rows by start date and sums NETWR_EURX so you can see which days carry more scheduled value for the current filters.
    • Selecting dates in the calendar filters the table to the matching rows. From there you can copy the filtered rows into Excel or use them as the basis for further analysis.

General suggestion: use the Schedule view for day-to-day visibility, the Simulation view to test what-if scenarios, and the Source Data Table + revenue calendar view when you need to slice, filter or export the underlying schedule data.

System Link & API guide

1. Core data endpoint

GET /api/prodorderschedule
Main endpoint used by all three views. The backend loads three SAP ODC sources defined by ODBC_ODC_PATH_PRODORDERSCHEDULE, ODBC_ODC_PATH_BACKLOG and ODBC_ODC_PATH_BACKLOG_COMMENT, then joins them by Sales Order and Item. Each row includes the original schedule fields plus NETWR_EURX, OmPeriod and ProductionLine. The JSON shape is { ok, rowCount, rows }.

2. Data sources used by this system

  • ODBC_ODC_PATH_PRODORDERSCHEDULE — SAP Production Order Schedules ODC. Provides core timing and order fields such as Startdate, Enddate, Starttime, Endtime, Acthrs, Rem hrs, Stdhrs, Totalqty, Workcenter, Salesorder, Item, Order, Material and Short text.
  • ODBC_ODC_PATH_BACKLOG — Sales backlog ODC. Supplies NETWR_EURX (estimated net value per order item) and, where available, Production Line information keyed by Sales Doc and Item.
  • ODBC_ODC_PATH_BACKLOG_COMMENT — Backlog comments ODC. Supplies OmPeriod and related comments, again keyed by Sales Doc and Item, used mainly in the data table and filters.

3. Simulation & uploads (client-side)

Excel uploads
The Simulation view reads Excel files directly in the browser using XLSX. No additional API endpoint is used: the uploaded file is parsed client-side and normalized into the same structure as the schedule rows before being rendered in the editable table and Gantt.

4. Additional fields from backend

NETWR_EURX
Estimated net value for each order item, imported from the backlog source so the Source Data Table and revenue calendar can show simple value totals.
OmPeriod
Period / remark field from the backlog comments source (for example financial year period or business comments), shown in the table and available for filtering.
ProductionLine / productionLine
Production line label inferred from backlog data and returned in both Pascal- and camel-case. Used by the Production Line filter in the data table and for grouping in external reporting.

5. Responses & error handling

All endpoints return JSON. On success, /api/prodorderschedule returns an ok flag, a rowCount and a rows array. On failure it returns HTTP 4xx/5xx codes with an error message, for example when one of the ODBC paths is missing or an import fails. If something does not load as expected in the UI, check the browser Network tab for the failing request and server error text.
