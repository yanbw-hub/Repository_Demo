Guide Manual

This guide explains how to use the main pages inside the Backend Status System. It is built around a fixed backlog file and derived JSON data, and exposes center views, dashboards and admin-only monitoring.

  1. Dashboard

    The Dashboard is the landing page of the Backend Status System. It aggregates backlog rows from the fixed backlog file and shows PMAD vs OM Period, status counts, and center-level distributions.

    • Use the OM Period and simple search filters to focus on a particular month, customer, or sales order range.
    • Read the top canvas charts to understand backlog volume by OM Period and CRATED quantity before drilling into tables.
    • Use this page when you need a quick answer to “How many orders are currently at risk or overdue, and in which centers?”.
  2. Center views (STRIP, CRIMP, WELD2, BLAST, CLEAN, PAINT, TESTLAB, DETAIL, CRATE)

    Each center tab shows a filtered view of the backlog for that workcenter, split into Pending and history / live work.

    • Use the Pending table to see all open orders the center is responsible for. You can sort, filter and export these rows.
    • Fields such as Priority, NotFinished and Why are editable; changes are written back to the shared backlog file and to the order edits store.
    • Double-click the Why column to open the notes editor, or press Enter on a selected row to open the sales-status modal.
  3. Live work & Material Check (per center)

    Under each center tab, the Orders Currently Being Worked On card combines live shop-floor confirmations with a structured material-check list.

    • The left side shows Live Workcenter Confirmations, refreshed automatically every 30 seconds from SAP confirmations.
    • The right side shows a Material Check table for that center, tied to the same pending orders. Use this before starting work to confirm that key materials and dependencies are available.
    • Export both Pending and History / Currently Working tables to CSV when preparing for daily stand-ups or shift handovers.
  4. CRATED Orders

    The CRATED tab isolates orders that are fully crated or ready to ship, based on the CRATED flag in the backlog file.

    • Use this tab to review what is already boxed or staged for shipping, and to confirm alignment with shipping schedules.
    • Export the CRATED table when coordinating with logistics or updating external stakeholders.
  5. History

    The History tab collects finished-history rows and the material-check history across centers. It is primarily for traceability and audit trail when reviewing past decisions.

    • Use this page when you need to answer “When did we last work on this order and what was the material status at that time?”.
    • Filter and export history when preparing reports for supervisors or when investigating recurring issues.
  6. Overdue Orders (Only for Admin)

    This tab is visible only when logged in as Admin. It reads from the raw backlog dataset and applies the overdue logic using OM Period and PMAD dates.

    • Use filters to focus on a specific plant, customer, or OM Period, then export the view for escalation.
    • Use this page to cross-check that the visual backlog status matches the raw ODC / OMS data and to validate overdue definitions.
  7. Notes (“Why”) and comments (Only for Admin)

    The Why field and associated comments store lightweight explanations for why an order is or is not finished.

    • Double-click the Why column or press Enter to open a modal where you can record reasons, risks or next steps.
    • These notes are stored separately in the order edits and comments structures so they survive refreshes.
    • Use this consistently so supervisors and planners can understand context without re-reading emails.
  8. Roles, login and “View As”

    Access to pages and editing capabilities depends on the user role (Admin, Supervisor, Other User).

    • Log in with your assigned username and password. Use the change-password modal to update your credentials when required.
    • Admins can use the View As control to see exactly what Supervisors or Users see, without changing data ownership.
    • Use this when testing changes to permissions or confirming whether a given user will be able to see a specific overdue group.

General Suggestion: use the Dashboard to spot problems, center tabs to see who owns them, the Overdue Orders page to validate logic against raw data, and the History and Material Check views when you need to understand past decisions.

1. Core backlog & OMS data

GET /api/files
List available data files in the backend data folder (for example the fixed backlog file and raw backlog JSON).
GET /api/data?file=BacklogDatabase.json
Load the main backlog dataset (status, OM Period, PMAD, CRATED, remaining hours). Feeds Dashboard, center Pending tables and CRATED view.
GET /api/data?file=BacklogRaw.json
Load the raw backlog rows used by the Overdue Orders admin page and supporting maps.
POST /api/update
Persist a single cell change back to the underlying backlog store. Payload includes { file, order, center, field, value }.

2. Order edits & comments

GET /api/order_edits
Fetch stored overrides for orders (for example Priority and Why notes) so they can be re-applied after file reload.
POST /api/order_edits
Upsert a single override such as { order, field, value } when a user changes Priority or Why in the grid.
GET /api/comments
Load per-order free-text comments used by the Why and notes dialogs.
POST /api/comments
Save or update a comment for a given Sales Doc./Item combination.

3. Live workcenter confirmations

GET /api/workcenter/confirmations?name=PAINT
Return live SAP confirmations for a single workcenter (used by the LiveWorkcenterConfirmations panel).
GET /api/confirmations/workcenters
Aggregate live confirmations by workcenter, so the Dashboard can show which centers currently have running work.

4. Material checks

GET /api/material_checks
Fetch all material-check entries across centers for use in history and audit views.
GET /api/material_checks/by_workcenter?name=PAINT
Filter material checks for a specific center. Used in the Material Check table under each Pending view.
POST /api/material_checks/save
Save or update a single material-check record when a user edits the checklist for one order.
POST /api/material_checks/bulk_save
Bulk-save multiple material-check rows at once (for example after editing several orders then committing the batch).

5. Refresh & status endpoints

POST /api/tableau/refresh
Trigger a Tableau-based export to rebuild the latest backlog file from source dashboards.
GET /api/tableau/status
Poll Tableau refresh status for display in the UI (success, running, or error message).
POST /api/om/refresh
Kick off a job to refresh OM Period mapping data from the upstream OMS / database source.
GET /api/om/status
Check the status of the OM Period refresh job.
POST /api/refresh_backlog
Rebuild the main backlog JSON (for example BacklogDatabase.json and BacklogRaw.json) from current source files.
GET /api/backlog/status
Report whether the last backlog refresh succeeded, and when it last completed.

6. Responses & errors

All endpoints return JSON. On failure the server uses HTTP 4xx/5xx codes and includes ok:false and an error message so you can quickly see what went wrong in the browser Network tab.
