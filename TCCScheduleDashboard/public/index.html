Schedule Visualization System

Interactive Gantt-style views for Winding & Roving, used for day-to-day sequencing, visualizing machine loading, and quick simulations.

Guide Manual
  1. Dashboard

    The Dashboard is the home page of the TCC Scheduling & Visualization: Integrated Platform. It summarizes backlog, load vs capacity, reworks and vacation status in one place so planners and managers can quickly see where to focus.

    • Use this page at the start of the day to scan key metrics: open backlog, overdue share, upcoming capacity risk and reworks trends.
    • When a metric looks off (for example, high overdue or high load ratio), click through to the related page (Backlog Summary, Load vs Capacity, Reworks, etc.) from the sidebar to investigate.
    • Treat this page as a “control tower” – it does not change data itself, but points you to the right detailed view for action.
  2. Backlog Summary (SAP Orders)

    This page reads all preloaded SAP and joined tables and presents them as backlog summary views. It combines SAP orders, TCC backlog, vacation capacity and derived metrics (e.g., EURx) so that you can see backlog by period, line and PMAD month.

    • In the table selector, pick which dataset you want to see (e.g. Winding & Roving, TCC Backlog, Vacation tables). The grid below will refresh to show that table.
    • Use the PMAD / forecast charts and stacked bars to see backlog volume by month and by line. Click on chart segments that are interactive to open “contributing orders” drilldowns.
    • When the PMAD drop-box is expanded, review which orders are driving a specific bucket, and use the Download Contributing Orders button to export those rows to CSV for sharing or deeper analysis.
    • Use this page when you want a clean, structured view of all SAP / backlog data and need to export or filter at order level.
  3. Prod Orders Schedule

    This is the main Gantt-style schedule for Winding & Roving. It visualizes SAP schedules as bars on a time axis, grouped by work center / line, and overlays backlog and PMAD information where available.

    • Use the schedule type selector to choose between L1, L2, and VPI schedules in SAP.
    • Use the line filter (WIND1–WIND5 or ALL) to focus the view on one line or see all lines together.
    • Adjust the date range (start and end) to define the planning horizon (for example, the next 4–6 weeks).
    • Each bar represents an order on a machine. Hover to see order details (material, coils, dates, clean flag, etc.).
    • Use this page when you want to visually check if the SAP schedule is realistic for each line, or to find slots where new orders might be inserted.
  4. Prod Orders Simulation

    This page runs a capacity-driven simulation of the backlog. It uses the same joined data and capacity tables, then simulates when orders would realistically finish under different assumptions (working days, capacity per day, and queue logic).

    • Set the simulation start date to tell the engine from which date to begin consuming capacity.
    • Adjust options such as which orders are included (for example, open backlog only, by line or by PMAD window) and how to treat weekends or non-working days.
    • Run the simulation to generate a table of simulated finish dates for each order. Compare simulated finish dates to PMAD to identify risk and needed actions.
    • Use this when someone asks, “If we start from today with current capacity, when will these orders realistically be completed?”
  5. Machine Load Simulation

    This page shows a machine-by-machine Gantt and allows interactive what-if planning. You can move orders between dates or adjust durations and store a simulated plan locally (and optionally on the server).

    • Set the date window (start and end) for the simulation horizon. The Gantt will show orders only inside this range.
    • Use the line filter (ALL or specific lines) to reduce the number of machines on screen.
    • Click a bar to open the edit drawer. Adjust fields such as PMAD, start date and duration to simulate moving or resizing that order.
    • Save overrides to local storage (and, if configured, to the server) to create a “what-if” plan without changing SAP.
    • Use this to visually confirm whether proposed changes (moving jobs, adding overtime days, etc.) can fit on the machines.
  6. Finish Date Simulation (Winding Variance)

    This page compares SAP schedules, Excel capacity/backlog sheets, and TCC backlog to show where finish dates or capacities do not line up. It is designed to highlight differences between planning sources.

    • Choose which line to focus on (where applicable) and whether to show tabs (SAP vs Excel) or a split view.
    • Use the quick filters at the top of each grid (for SAP and Excel) to search by order, material, or other fields.
    • Compare columns such as PMAD, planned dates and capacities across sources to understand why some orders look different in Excel vs SAP.
    • Use this when a question comes up like “Why is our Excel plan saying something different from SAP?” or “Where exactly are the date / volume mismatches?”
  7. Reworks

    The Reworks page tracks rework volume and patterns over time. It uses line charts and bar charts to show reworks by month, by failure mode and by department, plus underlying tables where needed.

    • Use the Top N slider to control how many leading failure modes or departments are displayed in charts.
    • Read the monthly trend line to see if reworks are getting better or worse, and which failure types are dominating.
    • Use this page during weekly or monthly reviews to identify where quality issues are costing capacity and to prioritize improvements.
  8. Vacation Management

    This page shows a vacation Gantt chart for key staff and work centers. It helps planners understand when capacity will be reduced due to people being away.

    • Use the date range pickers to set the window (default is roughly the next 3 months).
    • Filter by department (or “All”) and search by name to find specific employees or groups.
    • Each bar represents an employee’s vacation. Scan horizontally to see when multiple people are away at the same time.
    • When needed, use the refresh button to reload or rebuild the vacation Gantt from the latest source.
    • Use this when planning overtime or redistributing work around large vacation blocks (e.g. summer or holidays).
  9. Workcenter Information

    This page shows snapshot images of center-level information (e.g., center boards or local dashboards) for each line or area (LINE 1, LINE 2, VPI).

    • Select the desired view (LINE 1, LINE 2, or VPI). The snapshot for that area will load.
    • Use the refresh action when you want to pull a new snapshot from the backend, for example after center staff update their local boards.
    • This is read-only and intended to give planners visibility into local information without walking over to the physical boards.
  10. Scheduled Load Status

    This page summarizes scheduled vs remaining load by work center and period. It is designed as a table-driven status view where you can sort, filter and scan which centers are overloaded or under-loaded.

    • Use column filters or quick filters to focus on a specific line, machine or period.
    • Sort by key metrics (for example, load ratio or remaining hours) to bring the most critical centers to the top.
    • Use this when you need a compact, tabular answer to “Which centers are in trouble this week or next week?”
  11. Load vs Capacity

    This page shows a bar chart of monthly load vs capacity, plus a load ratio line. It is meant for high-level capacity discussions with Production and Management.

    • Use the filters (month range, line / work center selections, clean vs not clean treatment if applicable) to define what is included.
    • Read each bar as blue = confirmed load and overlay segments as simulated or added load. The line above the bars shows the load ratio (Load ÷ Capacity).
    • Hover over bars to see exact numbers for load, capacity and ratio for that month.
    • Use this when someone asks “Are we above or below capacity in the next few months?” or when validating scenarios created in the simulation pages.

General Suggestion: the sidebar pages are designed to work together. Start on Dashboard to find issues, use Backlog Summary, Prod Orders Schedule, Simulation and Machine Load Simulation to test solutions, and rely on Load vs Capacity and Reworks to communicate the impact to Management.

Load saved machine-by-machine override plan for the Machine Load Simulation page.
PUT /api/gantt_overrides

DELETE /api/gantt_overrides
Clear stored overrides and revert back to SAP-only schedule data.
3. Vacations & center snapshots
GET /api/vacations/gantt
Current vacation rows used by the Vacation Gantt.
POST /api/vacations/refresh
Refresh vacation data from Tableau and return the updated rows.
GET /api/centerinfo/snapshot/info[…]
Snapshot URL and last-updated time for each view (line1, line2, vpi).
POST /api/centerinfo/snapshot/refresh[…]
Trigger a new PNG export from Tableau and return updated snapshot metadata.

All endpoints return JSON. On failure the server uses HTTP 4xx/5xx with the following code: ok:false, error:"…" or error:"…" for easier debugging in the browser Network tab.

Backend Status System

A backlog-focused view summarizing which orders are on-time, at-risk, or overdue based on OM Period, PMAD dates, and remaining hours.

Guide Manual
  1. Dashboard

    The Dashboard is the landing page of the Backend Status System. It aggregates backlog rows from the fixed backlog file and shows PMAD vs OM Period, status counts, and center-level distributions.

    • Use the OM Period and simple search filters to focus on a particular month, customer, or sales order range.
    • Read the top canvas charts to understand backlog volume by OM Period and CRATED quantity before drilling into tables.
    • Use this page when you need a quick answer to “How many orders are currently at risk or overdue, and in which centers?”.
  2. Center views (STRIP, CRIMP, WELD2, BLAST, CLEAN, PAINT, TESTLAB, DETAIL, CRATE)

    Each center tab shows a filtered view of the backlog for that workcenter, split into Pending and history / live work.

    • Use the Pending table to see all open orders the center is responsible for. You can sort, filter and export these rows.
    • Fields such as Priority, NotFinished and Why are editable; changes are written back to the shared backlog file and to the order edits store.
    • Double-click the Why column to open the notes editor, or press Enter on a selected row to open the sales-status modal.
  3. Live work & Material Check (per center)

    Under each center tab, the Orders Currently Being Worked On card combines live shop-floor confirmations with a structured material-check list.

    • The left side shows Live Workcenter Confirmations, refreshed automatically every 30 seconds from SAP confirmations.
    • The right side shows a Material Check table for that center, tied to the same pending orders. Use this before starting work to confirm that key materials and dependencies are available.
    • Export both Pending and History / Currently Working tables to CSV when preparing for daily stand-ups or shift handovers.
  4. CRATED Orders

    The CRATED tab isolates orders that are fully crated or ready to ship, based on the CRATED flag in the backlog file.

    • Use this tab to review what is already boxed or staged for shipping, and to confirm alignment with shipping schedules.
    • Export the CRATED table when coordinating with logistics or updating external stakeholders.
  5. History

    The History tab collects finished-history rows and the material-check history across centers. It is primarily for traceability and audit trail when reviewing past decisions.

    • Use this page when you need to answer “When did we last work on this order and what was the material status at that time?”.
    • Filter and export history when preparing reports for supervisors or when investigating recurring issues.
  6. Overdue Orders (Only for Admin)

    This tab is visible only when logged in as Admin. It reads from the raw backlog dataset and applies the overdue logic using OM Period and PMAD dates.

    • Use filters to focus on a specific plant, customer, or OM Period, then export the view for escalation.
    • Use this page to cross-check that the visual backlog status matches the raw ODC / OMS data and to validate overdue definitions.
  7. Notes (“Why”) and comments (Only for Admin)

    The Why field and associated comments store lightweight explanations for why an order is or is not finished.

    • Double-click the Why column or press Enter to open a modal where you can record reasons, risks or next steps.
    • These notes are stored separately in the order edits and comments structures so they survive refreshes.
    • Use this consistently so supervisors and planners can understand context without re-reading emails.
  8. Roles, login and “View As”

    Access to pages and editing capabilities depends on the user role (Admin, Supervisor, Other User).

    • Log in with your assigned username and password. Use the change-password modal to update your credentials when required.
    • Admins can use the View As control to see exactly what Supervisors or Users see, without changing data ownership.
    • Use this when testing changes to permissions or confirming whether a given user will be able to see a specific overdue group.

General Suggestion: use the Dashboard to spot problems, center tabs to see who owns them, the Overdue Orders page to validate logic against raw data, and the History and Material Check views when you need to understand past decisions.

Report whether the last backlog refresh succeeded, and when it last completed.

Load vs Capacity Platform (For Sales)

High-level view of monthly loads vs capacity for Winding & Roving, with interactive 3D charts, machine-level insights and a simulation playground to support capacity decisions.

Guide Manual
  1. Purpose & when to use

    The Load vs Capacity platform shows, month by month, how much work is scheduled versus how much capacity we have, using the same Winding / Roving schedule and capacity extracts as the production planning tools. It focuses on forward-looking capacity checks rather than order-by-order detail.

    • Use it at the start of the week or month to see whether upcoming periods are overloaded or under-utilized by line.
    • Use it in conversations with Production / Management / Sales to show whether proposed plans fit existing capacity.
    • Combine it with the detailed Gantt and simulation tools when you need to move specific orders or add overtime.
  2. Top filters & modes

    The filter bar at the top of the Lines and Simulation sections controls what is included in the 3D chart and tables.

    • Production Line: choose Line 1, Line 2 or VPI. Only machines that belong to that line are included.
    • Process: toggle between Winding and Roving. This switches the hour fields and date fields used to calculate loads (Wind Hours + Winding Start/End vs Rove Hours + Rove Start/End).
    • Machine chips: once a line is selected, use the machine chips (All or a specific machine) to narrow the chart and insights to a single work center when needed.
    • Changes in these filters immediately recalculate the monthly series and all insights. The chart only shows months from the current month onward.
  3. Reading the 3D chart

    The main 3D chart shows 12+ months on the x-axis and load / capacity on the y-axis. Each month has a load bar and a capacity bar, plus a 3D load-ratio line running above the bars.

    • In the base view, the load bar is split into Clean and Not Clean hours. In Simulation, the base of the bar is the confirmed load, with extra simulated hours stacked on top in different colours per user.
    • The capacity bar shows total available hours for the same month, based on the capacity Excel extract.
    • Hover a bar to see an on-chart tooltip with Load, Capacity and Utilization %.
    • Use the toolbar in the top-left of the chart: Reset View, Auto-Rotate, Show / Hide Labels, Show / Hide Insights and Download PNG. Click once on the chart to activate 3D controls, then drag to rotate or scroll to zoom.
  4. Insights overlay & PMAD split

    When Insights are enabled, a glass-style panel appears over the chart with additional context for the selected line and, if applicable, machine.

    • Machine Design Spec: line-specific rules explaining which designs each machine is intended to run.
    • PMAD split pie: a pie chart showing how many orders have Promised MAD in the current month, next month, future months, or previous months for the selected line.
    • Top-utilization machines: a list with small bars showing total winding load ratio by machine, sorted from highest to lowest utilization.
    • Per-machine PMAD pies: for the top machines, small pies show the same current / next / future / previous MAD split. Clicking a segment opens the contributing orders for that bucket.
  5. Orders panel & simulation playground

    The platform lets you drill down from monthly bars into individual orders, and run simple what-if simulations on top of the confirmed schedule.

    • Orders side panel: click a month in the 3D chart (or a PMAD bucket in the machine pies) to open a slide-in panel with the contributing orders. Columns include Sales Order, Item, Production Order, hours and Clean flag.
    • Use the Download CSV button in that panel to export the current list for offline review or sharing.
    • In the Simulation section, the left-hand table (“Simulation Playground”) shows simulated load vs capacity by month. Use + Add to add hours by month and user, and Manage to delete remaining simulated hours.
    • The Transfer Simulation to Confirmed Schedule window lets you move some of the simulated hours into the confirmed load series. Simulation data is stored in the browser (localStorage), so each user keeps their own scenario.

General suggestion: use the Lines view for a clean month-by-month capacity picture, the Simulation view to test scenarios, and the orders panel when you need a list of concrete orders behind a month or PMAD bucket.

API guide for Data Source
1. Core data endpoints
GET /api/files
Lists all files in the server data directory (Excel / CSV / JSON), filtered to known formats and sorted by last modified time. Useful for checking which extracts are currently available to the app.
GET /api/data?file=<name>
Loads and parses a single data file. Supports .xlsx, .xlsm, .xls, .csv and .json. For Excel, the server reads the Schedule sheet if present, otherwise the first sheet, uses the first row as headers and returns an array of JSON rows with trimmed column names.
2. Files used by this platform
  • casbq0020a.trench-group.net TCC capacity.xlsx — daily capacity by work center. The app reads WorkCenter, calender_date / Calender_date and Capacity, then aggregates to monthly capacity per line / machine.
  • WR_Schedule.xlsx — Winding & Roving schedule. Key columns include Machine, Winding Start, Winding End, Rove Start, Rove End, Wind Hours, Rove Hours, Material, Promised MAD, Sales order, Item, Production Order and CLEAN. These are used to build monthly load, PMAD splits and the contributing orders lists.
3. Single-cell updates (optional)
POST /api/update
Updates a single cell in the cached data for a given file. The payload is { file, order, field, value }, where order matches the row’s Order column. For Excel sources, the server writes the result back as a “_modified” copy in the same directory. This endpoint is available for future admin tooling; the current UI remains read-only.
4. Comments store
GET /api/comments
Returns all saved comments from data/comments.json as a simple map { salesDoc: comment }.
POST /api/comments
Adds or removes a comment. Payload: { salesDoc, comment }. Sending an empty or missing comment deletes the entry. This can be used by future UI components to store notes against specific sales documents.
5. Responses & error handling

All endpoints return JSON. On success, the data endpoints return arrays of row objects; on failure they return HTTP 4xx/5xx codes with an error message. When something does not load as expected in the UI, check the browser Network tab for the failing request and server error text.
