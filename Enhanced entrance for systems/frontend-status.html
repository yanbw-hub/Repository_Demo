Frontend Status System

Planner-facing, read-oriented view of order status across all workcenters. Shares the same backlog and OM Period data model as the Backend Status System, simplified for quick review rather than shop-floor editing.

Backlog / OM Period logic Planner-facing view

How to use this System

  • Use your assigned credentials to log into the system
  • Filter by workcenter or search by Sales Doc, Material or Customer
  • Click a row to see routing history and linked comments
  • Data auto updates from SAP every 30 mins
  • This is a read-oriented view; use Backend Status System to edit Priority, Why notes or material checks

Guide Manual

This guide explains how to use the main pages inside the Frontend Status System. It reads the same fixed backlog file and derived JSON data as the Backend Status System, but is organized around quick review rather than center-by-center editing.

  1. Overview dashboard

    The landing page summarizes the whole backlog with four headline tiles — total orders, on-time %, at-risk and overdue — plus a six-month trend of how that mix has moved.

    • Use this page for a fast, planner-level read of overall health before drilling into a specific workcenter.
    • Watch the trend chart for a rising overdue share across consecutive months — an early signal worth escalating.
  2. Workcenter filter & search

    Orders can be filtered to a single workcenter (STRIP, CRIMP, WELD2, BLAST, CLEAN, PAINT, TESTLAB, DETAIL, CRATE) or viewed across all centers, and narrowed further with a free-text search across Sales Doc, Material and Customer.

    • Use this when a customer or account manager asks about a specific order or material without needing SAP access.
  3. Order detail panel

    Selecting a row expands a read-only detail panel with OM Period, routing/workcenter history, the latest linked comment from Backend Status, and a last-updated timestamp.

    • This panel never edits data directly — Priority, Why notes and material checks are still owned by the Backend Status System.
  4. Roles & access

    All roles (Planner, Account Manager, Viewer) see the same read-only data; there is no Admin edit mode in this frontend, by design.

    • Use Backend Status System when a change to Priority, Why, or material-check status is actually needed.

General Suggestion: use this system for quick lookups and customer-facing status checks, and switch to the Backend Status System whenever an order needs its Priority, Why note or material check updated.

System Link & API guide for Data Source

Open the link from internal network. Use your assigned credential to log in the system. Please be advised that the system initial load will take about 1–2 minutes.

Open Frontend Status System

Demo preview Status: Normal

1. Core backlog & OMS data

GET /api/frontend/summary
Return headline counts (total, on-time, at-risk, overdue) across the whole backlog for the overview dashboard.
GET /api/frontend/orders
List orders with workcenter, OM Period, status and a short comment preview, filterable by workcenter and free-text search.
GET /api/frontend/orders/:id
Return the read-only detail record for a single order, including routing history and the latest linked comment.

2. Trend & reporting

GET /api/frontend/trend?months=6
Return the on-time / at-risk / overdue split for each of the last N months, used by the trend mini-chart.

3. Responses & errors

All endpoints return JSON and are read-only — this frontend never writes back to the shared backlog store. On failure the server uses HTTP 4xx/5xx codes with ok:false and an error message for troubleshooting in the browser Network tab.
