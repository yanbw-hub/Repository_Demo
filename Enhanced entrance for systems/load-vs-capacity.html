Guide Manual

The Load vs Capacity platform shows, month by month, how much work is scheduled versus how much capacity we have, using the same Winding / Roving schedule and capacity extracts as the production planning tools. It focuses on forward-looking capacity checks rather than order-by-order detail.

  1. Purpose & when to use

    Use this platform when you want a high-level, month-by-month picture of whether lines are overloaded or under-utilized, instead of drilling into individual orders.

    • Use it at the start of the week or month to see whether upcoming periods are overloaded or under-utilized by line.
    • Use it in conversations with Production / Management / Sales to show whether proposed plans fit existing capacity.
    • Combine it with the detailed Gantt and simulation tools when you need to move specific orders or add overtime.
  2. Top filters & modes

    The filter bar at the top of the Lines and Simulation sections controls what is included in the 3D chart and tables.

    • Production Line: choose Line 1, Line 2 or VPI. Only machines that belong to that line are included.
    • Process: toggle between Winding and Roving. This switches the hour fields and date fields used to calculate loads (Wind Hours + Winding Start/End vs Rove Hours + Rove Start/End).
    • Machine chips: once a line is selected, use the machine chips (All or a specific machine) to narrow the chart and insights to a single work center when needed.
    • Changes in these filters immediately recalculate the monthly series and all insights. The chart only shows months from the current month onward.
  3. Reading the 3D chart

    The main 3D chart shows 12+ months on the x-axis and load / capacity on the y-axis. Each month has a load bar and a capacity bar, plus a 3D load-ratio line running above the bars.

    • In the base view, the load bar is split into Clean and Not Clean hours. In Simulation, the base of the bar is the confirmed load, with extra simulated hours stacked on top in different colours per user.
    • The capacity bar shows total available hours for the same month, based on the capacity Excel extract.
    • Hover a bar to see an on-chart tooltip with Load, Capacity and Utilization %.
    • Use the toolbar in the top-left of the chart: Reset View, Auto-Rotate, Show / Hide Labels, Show / Hide Insights and Download PNG. Click once on the chart to activate 3D controls, then drag to rotate or scroll to zoom.
  4. Insights overlay & PMAD split

    When Insights are enabled, a glass-style panel appears over the chart with additional context for the selected line and, if applicable, machine.

    • Machine Design Spec: line-specific rules explaining which designs each machine is intended to run.
    • PMAD split pie: a pie chart showing how many orders have Promised MAD in the current month, next month, future months, or previous months for the selected line.
    • Top-utilization machines: a list with small bars showing total winding load ratio by machine, sorted from highest to lowest utilization.
    • Per-machine PMAD pies: for the top machines, small pies show the same current / next / future / previous MAD split. Clicking a segment opens the contributing orders for that bucket.
  5. Orders panel & simulation playground

    The platform lets you drill down from monthly bars into individual orders, and run simple what-if simulations on top of the confirmed schedule.

    • Orders side panel: click a month in the 3D chart (or a PMAD bucket in the machine pies) to open a slide-in panel with the contributing orders. Columns include Sales Order, Item, Production Order, hours and Clean flag.
    • Use the Download CSV button in that panel to export the current list for offline review or sharing.
    • In the Simulation section, the left-hand table ("Simulation Playground") shows simulated load vs capacity by month. Use + Add to add hours by month and user, and Manage to delete remaining simulated hours.
    • The Transfer Simulation to Confirmed Schedule window lets you move some of the simulated hours into the confirmed load series. Simulation data is stored in the browser (localStorage), so each user keeps their own scenario.

General suggestion: use the Lines view for a clean month-by-month capacity picture, the Simulation view to test scenarios, and the orders panel when you need a list of concrete orders behind a month or PMAD bucket.

1. Core data endpoints

GET /api/files
Lists all files in the server data directory (Excel / CSV / JSON), filtered to known formats and sorted by last modified time. Useful for checking which extracts are currently available to the app.
GET /api/data?file=<name>
Loads and parses a single data file. Supports .xlsx, .xlsm, .xls, .csv and .json. For Excel, the server reads the Schedule sheet if present, otherwise the first sheet, uses the first row as headers and returns an array of JSON rows with trimmed column names.

2. Files used by this platform

  • casbq0020a.trench-group.net TCC capacity.xlsx — daily capacity by work center. The app reads WorkCenter, calender_date / Calender_date and Capacity, then aggregates to monthly capacity per line / machine.
  • WR_Schedule.xlsx — Winding & Roving schedule. Key columns include Machine, Winding Start, Winding End, Rove Start, Rove End, Wind Hours, Rove Hours, Material, Promised MAD, Sales order, Item, Production Order and CLEAN. These are used to build monthly load, PMAD splits and the contributing orders lists.

3. Single-cell updates (optional)

POST /api/update
Updates a single cell in the cached data for a given file. The payload is { file, order, field, value }, where order matches the row's Order column. For Excel sources, the server writes the result back as a "_modified" copy in the same directory. This endpoint is available for future admin tooling; the current UI remains read-only.

4. Comments store

GET /api/comments
Returns all saved comments from data/comments.json as a simple map { salesDoc: comment }.
POST /api/comments
Adds or removes a comment. Payload: { salesDoc, comment }. Sending an empty or missing comment deletes the entry. This can be used by future UI components to store notes against specific sales documents.

5. Responses & error handling

All endpoints return JSON. On success, the data endpoints return arrays of row objects; on failure they return HTTP 4xx/5xx codes with an error message. When something does not load as expected in the UI, check the browser Network tab for the failing request and server error text.
