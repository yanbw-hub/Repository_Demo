Production Work Center Andon Board

Large-screen, workcenter-based view of today's production orders, combining live confirmations from ForeSoght with planned hours and planned time windows from SQL ProdOrderSchedule database to support on-the-floor conversations and shift handovers.

Guide Manual

This guide explains how to use the Production Order Andon Board for daily line-up, stand-up meetings and shift handovers. It reads live confirmations from the LUSCA database and planned hours / time windows from the ProdOrderSchedule ODC file, and presents a single "today" view per workcenter.

  1. Andon board overview

    The Andon board is the landing view. It always focuses on one workcenter at a time and shows orders whose start time is today. The top summary band aggregates total plan hours, total actual hours and the Dev Accum. for all orders currently on the board.

    • Change the Workcenter in the header to switch to a different line or center.
    • Use this board when you need a quick answer to "What is running now, what is next, and how are we tracking against plan today?".
    • Keep the board open on a large screen close to the work area throughout the shift so everyone can see the current sequence and status.
  2. Workcenter selection & search

    The header area of the Andon board contains a Workcenter search box and a dropdown. These are populated from the distinct list of workcenters in the underlying confirmations table.

    • Use the search box to type part of a workcenter name; the board will highlight the first match and update the dropdown.
    • Use the dropdown when you want to directly jump to another workcenter.
    • While the board is loading data, the controls are temporarily disabled to avoid switching workcenters mid-refresh.
  3. Summary band (Plan / Actual / Dev Accum.)

    The summary band at the top of the table shows three core metrics for today's orders in the selected workcenter: Plan Hours, Actual Hours and Dev Accum..

    • Plan Hours comes from the planned hours in ProdOrderSchedule (Stdhrs) aggregated by production order and matched to the confirmations.
    • Actual Hours is calculated from the confirmed start and end times (or from the database actual time field) for completed orders.
    • Dev Accum. is the difference (Actual minus Plan) across all completed orders for that workcenter today; the text is green when the center is on or ahead of plan and red when it is behind plan.
  4. Main table (STEP, SEQ, ITEM, STD HRs, PLAN TIME, ACTUAL TIME, STATUS)

    The main table lists today's orders for the selected workcenter in the sequence they are or will be processed. Each row corresponds to one confirmation row grouped into a daily sequence.

    • STEP shows the position in the flow: Now, Next, subsequent SEQ n, or completed when everything is finished.
    • SEQ is a simple sequence number for today (1, 2, 3, …) based on serial number and start time.
    • ITEM displays the production order number (P.O.), normalized so that leading zeros do not matter when matching to ProdOrderSchedule.
    • STD HRs shows the planned hours for that order in the selected workcenter, based on the joined schedule data.
    • PLAN TIME shows the planned start and end window for that order in the workcenter, as derived from ProdOrderSchedule.
    • ACTUAL TIME shows the confirmed start and end timestamp for the order today. If the end time is not yet recorded, the board shows XX:XX as the placeholder.
    • STATUS shows any comments or short text recorded in the confirmations table for that row.
  5. Colour logic & legend

    The Andon board uses a simple colour scheme so the status of each order can be read at a glance from across the shop floor.

    • The row marked as Now (in progress) is shown in blue and also gets an inset blue bar on the left of the row.
    • Future sequences without an end time are shown in grey; they still display their planned window and standard hours.
    • Completed orders are coloured green when the aggregated actual time for that production order is on or ahead of plan, and red when actual time has exceeded the planned hours.
    • Alternate dark backgrounds are used for readability when no special colour applies.
  6. Data scope and limits (today-only view)

    The Andon board focuses strictly on today's work in the selected workcenter. It is not intended to be a historical or multi-day analysis tool.

    • Only rows where the confirmation start time is on the same calendar day as the current time (America/Toronto time zone) are displayed.
    • When there are no matching rows, the board explicitly shows "No orders with today's start time.".
    • For older history or multi-day backlog analysis, use the Schedule Visualization, Load vs Capacity, or other reporting tools instead of the Andon board.
  7. Refresh behaviour & stability

    The board refreshes itself so it stays up to date without manual intervention, while avoiding unnecessary load on the data sources.

    • The frontend automatically calls the workcenter board endpoint every 2 minutes to update today's sequence and status.
    • The ProdOrderSchedule data is cached on the server so it is only refreshed at most once per day, even if the frontend is refreshed more often.
    • If an API error occurs, the board surfaces a red error chip but retains the last known-good data to avoid a blank screen during the shift.
  8. Daily use pattern & responsibilities

    The Andon board is designed as a shared visual tool. It does not implement per-user roles; instead, the use pattern is managed by supervisors and the scheduling team.

    • Supervisors or team leads decide which workcenter to show on the board at different times of day.
    • Use the board during stand-up meetings, start-of-shift checks and handovers to align on what is running now, what is next and how the center is tracking against plan.
    • When repeated issues or large negative deviations are observed, combine insights from the Andon board with detailed backlog and schedule reports to identify root causes.

General suggestion: use the Production Order Andon Board during the shift for live conversations about current work and plan vs actual, and use the Schedule Visualization, Load vs Capacity and backlog-style tools when you need a longer-term or cross-center view.

API guide for Andon Board

Open the Andon board from inside the internal network. For best results, run it in full-screen mode on a large monitor or TV in the work area. The initial load will take about 1–2 minutes while centers and today's data are loaded.

1. Workcenter list & live board data

GET /api/workcenter/list
Return the distinct list of workcenters from the confirmations table in the lusca Postgres database. Used to populate the Workcenter dropdown and search box in the Andon board header.
GET /api/workcenter/board?name=WELD2
Return all confirmation rows for the specified workcenter. The server sorts by serial and starttime; the frontend then filters to today's rows, calculates STEP / SEQ labels, applies colour logic and builds the table view.
Source: lusca.confirmations
Both endpoints read from the same underlying confirmations table. Only read-only SELECT queries are allowed; there are no write endpoints in this Andon board backend.

2. Planned schedule (ProdOrderSchedule ODC)

ODC path: ODBC_ODC_PATH_PRODORDERSCHEDULE
Environment variable pointing to the ProdOrderSchedule ODC file. The backend uses a helper to import this file and expose the data as JSON rows.
GET /api/prodorderschedule
Load rows from ProdOrderSchedule via the ODC helper. The server keeps up to the first 15,000 rows to protect memory. The frontend builds a plan-hours map from these rows to join against the confirmations (by normalized production order and workcenter).
GET /api/prodorderschedule?workcenter=WELD2
When a workcenter query parameter is provided, the server filters the schedule rows to that center before returning them. This allows callers to inspect just one center's planned hours if needed.

3. Join & normalization logic

Order & center normalization
Both backend and frontend normalize production order IDs (removing non-digits and leading zeros) and workcenter names (uppercasing and trimming) so that values from confirmations and ProdOrderSchedule can be reliably matched.
Plan hours & planned window fields
After the join, each confirmation row may receive additional fields: planHoursFromSchedule and planned start / end date / time fields. These are used to compute STD HRs and the PLAN TIME text for each row in the Andon board.

4. Refresh & caching behaviour

ProdOrderSchedule cache (24h)
The server caches the ProdOrderSchedule data in memory and reloads it at most once every 24 hours. Subsequent calls to /api/prodorderschedule during that window return the cached rows.
Frontend auto-refresh (2 min)
The React frontend calls /api/workcenter/board on a fixed interval (every 2 minutes) for the currently selected workcenter, rebuilding today's sequence while keeping the board open on screen.

5. Deployment & URL

Default port: 5004
By default the Andon board backend listens on port 5004. The same process serves the built React app and the JSON APIs, so the browser only needs to talk to one host:port.
Static React build
The client/build folder is served as static assets. Unknown routes fall back to index.html so the frontend router can handle navigation.

6. Responses & errors

All endpoints return JSON. On failure the server uses HTTP 4xx/5xx codes and includes ok:false and an error message where applicable so you can quickly see what went wrong in the browser Network tab or in logs.
